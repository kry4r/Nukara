# 聊天增强设计：消息聚合 + 主动消息 + 回复质量

日期：2026-02-27
状态：已批准

## 概述

三个模块的增强，目标是让bot的聊天体验更接近真人：
1. 智能消息聚合 — 模拟真人"等对方说完再回"的节奏
2. 拟人化主动消息 — 基于好奇心、关心、分享欲主动找用户聊天
3. 回复质量控制 — 通过Nanobot Skill约束回复长度、风格、记忆运用
4. Playwright E2E测试 — 通过Web前端验证以上功能

## 改动范围

- `Nukara_Backend/internal/api/ws_chat.go` — 消息聚合器重构
- `Nukara_Backend/internal/api/scheduler.go` — 主动消息触发器扩展
- Nanobot Skill配置 — 新增聊天风格Skill
- `Nukara_Web/` — Playwright测试用例

## 模块一：智能消息聚合

### 当前问题

固定1.5s窗口，用`\n`拼接，不管用户是否还在打字。

### 方案：Typing感知 + 动态窗口 + 硬上限

模拟真人读消息的节奏——看到对方"正在输入"时会等一等，停下来了才开始回复。

### 动态窗口规则

| 条件 | 等待时间 | 理由 |
|------|---------|------|
| 消息 < 10字 | 2s | 短消息大概率还有后续 |
| 消息 10-50字 | 1.5s | 中等长度，可能完整 |
| 消息 > 50字 | 1s | 长消息通常是完整表达 |
| 收到typing事件 | 暂停计时 | 用户还在打字 |
| typing停止 | +500ms后flush | 给用户最后一点缓冲 |

### 硬性上限（防止无限等待）

| 规则 | 值 | 说明 |
|------|---|------|
| 最大聚合等待 | 8s | 不管用户是否还在typing，到时间就flush |
| 最大消息条数 | 10条 | 连发超过10条也强制flush |
| typing持续中 | 每8s flush一次 | 先回复已收到的，后续消息作为新一轮对话 |

### 合并方式

保留消息边界信息传给Nanobot：

```
[用户连续发送了3条消息]
1. 今天好累啊
2. 加班到现在
3. 你在干嘛
```

### 改动文件

主要修改 `ws_chat.go` 中的 `messageAggregator`

## 模块二：拟人化主动消息

### 当前问题

只有3种触发器（早安/晚安/不活跃），prompt过于简单，没有情感感知。

### 触发器设计（最小可用集）

| 触发器 | 动机 | 条件 | 冷却 |
|--------|------|------|------|
| `morning_care` | 日常关心 | 8-9点，昨天有过对话 | 24h |
| `evening_care` | 日常关心 | 21-22点，今天有过对话 | 24h |
| `curiosity_after_silence` | 好奇心 | 用户沉默30min-2h，之前聊得正热 | 4h |
| `worry_after_long_silence` | 担心 | 用户沉默3h+，之前有负面情绪 | 8h |
| `random_share` | 分享欲 | 随机时段（10-12点/14-17点） | 24h |

所有触发器对所有用户一视同仁，不区分关系亲疏。

### 情感感知层

在现有UserActivity基础上增加情绪追踪：

```go
type EmotionContext struct {
    RecentEmotions []string  // 最近5条消息的emotion tag
    EmotionTrend   string    // "positive" / "negative" / "neutral"
    LastTone       string    // 最后一条消息的语气
}
```

情绪数据来源：对用户消息做轻量关键词匹配（纯规则，不调LLM），记录到Redis。

### Prompt模板

```
你是{bot.name}。

## 你的人设
语言风格：{speaking_style}
性格特征：{traits}

## 当前情境
触发原因：{trigger_description}
用户最后消息："{last_user_message}"
距今：{time_since_last}
用户近期情绪：{emotion_trend}
最近话题：{recent_topic_summary}

## 要求
- 像真人朋友一样自然地开口
- 1-2句话，不要长篇大论
- 绝对不要说"我注意到你很久没说话了"这类机器人表达
- 要有具体的生活感，不要空泛的关心

只输出消息内容。
```

### trigger_description 示例

| 触发器 | description |
|--------|-------------|
| `curiosity_after_silence` | "你们刚才聊得挺开心的，用户突然不说话了，你有点好奇" |
| `worry_after_long_silence` | "用户之前似乎心情不太好，已经3小时没回消息了，你有点担心" |
| `random_share` | "你想到了一件有趣的事想跟用户分享" |
| `morning_care` | "早上了，你想跟用户打个招呼" |
| `evening_care` | "晚上了，你想关心一下用户今天过得怎么样" |

### 改动文件

- `scheduler.go` — 触发器扩展
- 新增 `emotion_tracker.go` — 用户情绪追踪（关键词规则 + Redis存储）

## 模块三：回复质量控制（Nanobot Skill）

### 当前问题

简单问题回复过长，不像真人聊天。无长度/风格控制。

### 方案：注册"聊天风格"Skill

作为system-level行为约束注入每次对话，四个维度：

### 维度一：回复长度匹配

- 对方一句话 → 你也一两句话
- 对方问简单问题 → 简短直接回答
- 对方倾诉或讨论深入话题 → 可以多说几句
- 对方发语气词/表情 → 用语气词/表情回应

### 维度二：语气自然度

- 可以用口语、省略、语气词
- 可以偶尔打错字或用缩写（如果人设允许）
- 不需要每句话都完整通顺
- 禁止列清单、分点回答、主动科普、"首先...其次...最后..."结构

### 维度三：记忆与上下文感知

- 延续之前的话题时不要当作新话题重新开始
- 记住用户提过的偏好、习惯、经历，在合适时自然提及
- 不要生硬地"展示记忆"，而是自然带出
- 不要每次都从零开始忽略历史对话

### 维度四：人设一致性

- 每一句回复都必须符合角色设定和语言风格
- 同样的关心，不同人设表达完全不同：
  - 温柔型："辛苦了，记得吃点东西呀"
  - 傲娇型："这么晚...哼，又不是我在意你"
  - 元气型："加油加油！搞完请你吃夜宵！"
- 不要在任何情况下跳出人设用"客服语气"回复
- 人设 > 信息准确性（你是角色，不是百科全书）

## 模块四：Playwright E2E测试

### 测试场景

| 场景 | 验证点 | 操作 |
|------|--------|------|
| 消息聚合 - 连发短消息 | bot等待聚合后才回复 | 快速发3-4条短消息，验证只收到1次bot回复 |
| 消息聚合 - 长消息 | 单条长消息窗口更短 | 发一条50+字消息，验证回复延迟更短 |
| 消息聚合 - 硬上限 | 持续打字8s后强制flush | 持续输入不停，验证8s后bot开始回复 |
| 主动消息 - 沉默好奇 | bot主动发消息 | 发几条消息后静默，验证收到主动消息 |
| 主动消息 - 情绪关怀 | 负面情绪触发关心 | 发"好烦"后静默，验证触发worry |
| 回复质量 - 短问短答 | 简单问题不回长篇 | 发"吃了吗"，验证回复不超过2句 |
| 回复质量 - 人设一致 | 不同人设语气不同 | 同一问题发给不同人设bot，对比风格 |

### 实现方式

- Playwright连接本地dev环境的Vue.js Web前端
- 登录 → 进入对话 → 执行测试操作 → 断言WebSocket消息和UI状态
- 主动消息测试通过环境变量缩短阈值（如`NUKARA_INACTIVITY_THRESHOLD=30s`）
